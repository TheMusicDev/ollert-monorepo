# Planning Log

## 2026-08-19
* **Initialization**: Created the planning OKF bundle for Ollert (stripped-down Trello clone: CakePHP backend, Supabase Auth, Vite+React frontend).
* **Decisions**: MVP scope set to bare-bones (boards/lists/cards/drag-drop/board members, no roles). App data placed in CakePHP-owned MySQL, not Supabase Postgres — Supabase used auth-only. JWT verification set to JWKS/RS256 with HS256 documented as fallback. Repo layout set to monorepo (`/api`, `/web`, `/planning`).
* **Realtime reconsidered**: Initially requested for day 1, but Supabase Realtime requires the data to live in Supabase's own Postgres (it watches Postgres logical replication), which conflicts with the MySQL/CakePHP-owned-DB decision. Options were a self-hosted Pusher-protocol relay (Soketi) or SSE from CakePHP; user chose to drop realtime from MVP entirely rather than take on either now. Revisit in a later phase — see [Roadmap](roadmap.md).
* **Update**: Added `organizations` above boards — an org has many boards. Dropped `board_members`; added `org_members` instead. Access is org-scoped: any org member has access to every board under that org (no per-board membership/roles in v1). Updated [Data Model](data-model.md), [API Contract](api-contract.md), and [Roadmap](roadmap.md) accordingly.
* **Update**: Resolved the review items from `todos.md`. Added `max_orgs`/`max_boards_per_org` quota columns to `users` (defaults 1/3, app-enforced); board creation is now org-owner-only. JIT provisioning confirmed as find-or-create per request. CORS set to an origin allow-list with no credentials mode (Bearer-token auth, no cookies). Standard `{ error: { message, code, fields? } }` response envelope defined. Deployment: shared PHP host over SSH, local (non-CI) scripts split by package, writing them deferred to Phase 3. Testing stack set: PHPUnit / Vitest / Playwright (e2e). `cakephp/migrations` confirmed as the migrations tool. FE router set to TanStack Router as a plain client-side SPA — TanStack Start considered and rejected, since there's no Node server to run its SSR/server-functions model and forcing a "no SSR" mode fights the framework. Updated [Architecture](architecture.md), [Data Model](data-model.md), [API Contract](api-contract.md), and [Roadmap](roadmap.md) accordingly.

## 2026-08-19 (cont.)
* **Primary keys → UUID**: All entity PKs (and referencing FKs) switched from auto-increment int to UUID (`char(36)`, migrations `uuid` type). CakePHP's ORM auto-generates a UUID on save when the PK column type is `uuid`, so this needs no extra plugin/hook. `users.supabase_uid` remains a distinct UUID column from the new `users.id`.
* **FE framework reversed → TanStack Start**: Prior decision (this same day) picked plain TanStack Router specifically to avoid TanStack Start, since Start's SSR/server-functions model needs a Node server and the deploy target (shared PHP host) has none. User now wants Start regardless. Resolved by running Start in **SPA mode** — SSR and server functions disabled, static client build, same deploy shape (build + sync to PHP host) as the plain-Router plan it replaces. If the deploy target ever gains a Node runtime, SSR can be turned on.
* **FE toolchain**: Bun adopted as package manager/runtime for `/web` (replaces npm implicitly). Tailwind CSS and Base UI (headless component primitives) added for styling/components — no prior decision existed for either.
* Updated [Architecture](architecture.md), [Data Model](data-model.md), and [Roadmap](roadmap.md) accordingly. [API Contract](api-contract.md) unaffected (int vs. uuid IDs don't change endpoint shapes, just the ID string format in URLs/payloads).

## 2026-08-19 (cont. 2)
* **Timestamps/soft delete convention**: every table gets `created`/`modified` (core CakePHP `TimestampBehavior`, replacing the ad hoc `created_at`/`updated_at` names used in the first draft) and a `deleted` datetime via the `muffin/trash` plugin. All `DELETE /api/...` endpoints are now soft deletes.
* **List/card quotas added**: `max_lists_per_board` (default 5) and `max_cards_per_board` (default 100) added to `users`, checked against the org owner regardless of who's creating, same pattern as `max_orgs`/`max_boards_per_org`. Closes the previously-flagged gap where list/card counts were unbounded.
* Updated [Architecture](architecture.md), [Data Model](data-model.md), [API Contract](api-contract.md), and [Roadmap](roadmap.md) accordingly.
* **Remaining gaps**: everything else identified in the gap review (404 handling, pagination, API versioning, Supabase project/env vars, JWKS TTL, local dev story, PHP/Bun version pins, FE 401 handling, auth redirect URLs, visual design starting point, CI, fixture/seed strategy, field length/uniqueness rules, empty-list first position value) written up with options + recommendations in `gaps-found.md` (repo root) for review — not yet resolved.

## 2026-08-19 (cont. 3)
* **Pagination**: added to every top-level collection endpoint (`GET /api/orgs`, org members, org boards) — `?page=`/`?limit=` (default 20, clamp to 100), `{ data, meta }` envelope. Driven by the list/card quotas being per-user columns, not a fixed ceiling, so raised quotas could make these collections large. `GET /api/boards/:id`'s nested lists/cards stay unpaginated — a kanban board needs its full state to render/drag-drop, and `max_lists_per_board`/`max_cards_per_board` already bound that payload.
* **Root `.env.example` added**: documents every env var across `docker/`, `/api`, `/web` in one place (neither package is scaffolded yet). Supabase project itself not yet created — values are placeholders until then.
* **Docker dir reviewed**: user had already created `docker/docker-compose.yml` (MariaDB 11.8 + Mailpit) plus `docker/.env`/`docker/.env.example`. Confirmed workable. Found `docker/.env` and `docker/data/` weren't gitignored — fixed. Mailpit's purpose flagged as a placeholder (Supabase hosted auth emails bypass it; useful once CakePHP sends its own email). Documented in [Architecture](architecture.md#local-development).
* **PHP pinned to 8.5**, Bun pinned to **v1.3.14** (via `package.json`'s `packageManager` field, not a `.bun-version` file — not a real Bun convention).
* **Design starting point**: color palette, typography (Inter), shadow token, and layout pattern (sidebar/navbar/cards/tables) extracted from `windmill-dashboard-react`/`windmill-react-ui` (MIT) at the user's request — explicitly the tokens/pattern, not the `@windmill/react-ui` component library itself (unmaintained, Tailwind v1-era, would conflict with the Base UI choice). New concept doc **[Design](design.md)** added to the OKF bundle and linked from `index.md`.
* **Remaining gap-review items resolved** (user agreed with all standing recommendations): 404s use the standard error envelope (`code: "not_found"`); API versioning skipped (single consumer); JWKS TTL set to 15 min; FE treats 401 as unrecoverable (redirect to login, no retry-after-refresh); FE gains an `/auth/callback` route for Supabase redirects; no CI for the MVP; PHPUnit fixtures / ad hoc Vitest mocks / API-seeded Playwright for test data; `name`/`title` fields `varchar(255)` required no-uniqueness; empty-list first `position` bootstraps to `1.0`.
* Updated [Architecture](architecture.md), [Data Model](data-model.md), [API Contract](api-contract.md), [Roadmap](roadmap.md); added [Design](design.md). `gaps-found.md` (repo root) rewritten to show every item resolved, following the same pattern as `todos.md`.

## 2026-08-20

* **`.env.be.example` retired, superseded by `api/.env.example`**: now that `/api` is scaffolded, the root-level placeholder moved to live next to what it configures. Merged in the stock CakePHP skeleton's `api/config/.env.example` (added `APP_FULL_BASE_URL`, optional `DATABASE_TEST_URL`/`CACHE_*_URL`/`LOG_*_URL`/`EMAIL_TRANSPORT_DEFAULT_URL` DSN overrides), then deleted the stock file. `DB_HOST`/`DB_PORT`/`DB_DATABASE`/`DB_USERNAME`/`DB_PASSWORD` replaced by a single `DATABASE_URL` DSN. `.gitignore` updated (root: `.env.be` entry dropped; `api/.gitignore`: `/config/.env` → `/.env`).
* **`config/app_local.php` removed from the CakePHP scaffold**: no longer generated by `composer install`, no longer loaded by `bootstrap.php`. All per-environment config now flows through `.env` (loaded from `api/.env`, not the stock `api/config/.env`) into `app.php` directly — one config file instead of two. Full rationale and the DSN-over-discrete-vars convention this reinforces written up in `api/CakePHPDivergance.md` (new).
